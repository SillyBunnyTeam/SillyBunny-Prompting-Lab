# Product

## Register

product

## Users

SillyBunny users who maintain more than one character, preset, or macro pack and need to know
whether a change affected them. Card creators checking a card before release, preset authors
checking a preset against many characters, and extension developers checking that their extension
did not disturb prompts it does not own.

## Product Purpose

Prompting Lab saves a prompt configuration as a test case and rebuilds the prompt on demand, so a
user can see what a character, persona, preset, and profile actually produce, and compare that
against a saved result from before a change. It answers "did this change break anything?" across a
whole set of characters, rather than showing one prompt at a time.

## Brand Personality

Exact, unhurried, and honest about its own limits. The interface should state plainly what was
measured, what was estimated, and what a test run could not reproduce, so a user can trust a pass
and act on a failure.

## Anti-references

Avoid dashboards that imply precision they do not have, hidden automation that changes a user's
setup without saying so, silent truncation of results, red-and-green status with no explanation,
and developer jargon in place of plain description.

## Design Principles

- Report what was captured and what was skipped with equal prominence.
- Never leave a user's character, persona, preset, or profile changed after a run.
- Distinguish a difference from a failure; a difference invites review, a failure demands it.
- Keep noise out of comparisons so that a real change stands out.
- Follow SillyBunny's own navigation instead of inventing a parallel one.

## Accessibility & Inclusion

Support keyboard and screen-reader navigation, visible focus, semantic status updates, reduced
motion, coarse-pointer touch targets, responsive mobile layouts, and state cues that do not rely on
color alone. Aim for WCAG AA contrast and interaction behavior.
